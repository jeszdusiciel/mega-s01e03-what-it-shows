Triage: duplicate reports

owner support desk current reviewed 2026-10-29 · 0 days ago

A busy morning brings hundreds of reports about the same thing. We keep one ticket per issue and merge every duplicate into it, so engineering sees one thread with a count.

The rule

A report is a duplicate only when evidence supports the same failing path (decision 0002). This replaces the subject-only rule in the preserved historical decision 0001.

  1. Read the body and look up the tenant’s locale, form version and channel.
  2. Compare the failing path with an open ticket, checking contradictory symptoms.
  3. Merge only a supported match. Otherwise keep a separate ticket or investigate missing context.
  4. Count unique report IDs; preserve received and merged timestamps separately.
Same subjects can hide different failures; different subjects can describe the same one. The #4471 review shows how subject-only merging hid the booking-form hint problem.
